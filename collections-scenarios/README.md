# Collections and Scenarios

## ✨ At A Glance

Explains the public mental model for collections, leads, and scenarios so users understand organization versus analysis.

## 🎨 Reader Promise

> A new user should understand the product nouns quickly: collections organize work, leads represent opportunities, and scenarios carry the analysis.

## 🧭 How To Use This README

- Use this README when documenting how users structure investment work.
- Keep examples centered on user decisions: grouping work, reviewing opportunities, and comparing assumptions.
- Preserve the distinction that collections organize work while scenarios model analytical branches.

Collections help users organize related properties and opportunities. Scenarios help users model and compare assumptions inside those collections.

## 🧱 Core Concepts

- **Collection:** A top-level grouping for related investment work.
- **Lead:** A property or opportunity being reviewed.
- **Scenario:** A modeled branch of assumptions, metrics, and analysis.

## 🧭 When To Use Each One

- Create a collection when work belongs to a shared investment theme, portfolio, client, or review process.
- Add a lead when there is a property or opportunity to evaluate.
- Create a scenario when assumptions need to be modeled, compared, or saved as a distinct case.

## 🌐 Public Guidance

- Explain how collections, leads, and scenarios relate to each other.
- Make it clear that scenarios are analytical branches, not final decisions.
- Encourage users to compare scenarios using consistent assumptions and review context before acting.

## 🔑 Key Principle

Collections are organizational. Scenarios are analytical.

## 🛠️ Maintenance Notes

- Update this README when product language for collections, leads, or scenarios changes.
- Avoid internal database naming unless it is intentionally exposed to users.
