# Integrations

## At A Glance

Public guidance for user-visible connected workflows, external handoffs, and support expectations around integrations.

## How To Use This README

- Use this README to explain what users should expect before, during, and after an external handoff.
- Describe visible inputs, outputs, delays, and failure handling without exposing provider configuration.
- Ask users to capture workflow name, visible message, time, and affected record for support.

Public-facing guidance for workflows that connect Orion Rigel to external systems, documents, communication tools, or data handoffs.

## What Users Should Understand

- Where integration-related actions appear in the UI.
- What information or files may be required before a handoff.
- When a workflow depends on an external system.
- What to do if a connected workflow fails or appears delayed.

## Public Guidance

- Describe the visible workflow, expected inputs, and expected outputs.
- Explain when users should retry versus contact support.
- Ask users to include the workflow name, time of failure, visible message, and affected record when requesting help.

## Do Not Include

- Secret handling.
- Internal provider configuration.
- Private operational runbooks.
- Vendor credentials, webhook details, or privileged support procedures.

## Maintenance Notes

- Update this README when public integration workflows, handoff expectations, or support instructions change.
- Never include credentials, webhook secrets, provider setup, or private operational runbooks.
