# Simulations

## ✨ At A Glance

Public guide for running simulations, reviewing sensitivity-style outputs, comparing cases, and treating results as decision-support signals.

## 🎨 Reader Promise

> Users should understand simulations as ways to pressure-test assumptions, not as promises about the future.

## 🧭 How To Use This README

- Use this README when documenting how users select inputs, run simulations, and compare base cases with alternatives.
- Keep assumptions, outputs, and interpretation guidance connected.
- Point users to support when outputs appear inconsistent with visible inputs.

Simulation workflows help users test assumptions, compare outcomes, and review sensitivity across investment cases.

## ✅ What Users Can Do

- Select a collection, lead, or scenario to analyze.
- Run a simulation using available scenario assumptions.
- Review summary outputs and distribution-style results where available.
- Compare a base case against alternative cases.
- Save or revisit derived analysis when the product supports it.

## 🌐 Public Guidance

- Explain the workflow steps in the same order users see them.
- Describe outputs as decision-support signals, not guarantees.
- Encourage users to compare assumptions before comparing results.
- Point users to support when simulation output appears inconsistent with inputs.

## 🎯 Keep Public Docs Focused On

- Workflow steps.
- Safe interpretation guidance.
- Decision-support framing.

## 🛠️ Maintenance Notes

- Update this README when simulation entry points, visible output types, comparison behavior, or save behavior changes.
- Keep engine details, numerical limits, and internal execution logic in internal docs.
